# tuougm-sns-generator

SNS投稿を簡単に生成・管理するためのプロジェクトです。

## 概要
- SNS向けの文章生成をサポートするプロジェクト
- 文章の整形やテンプレート化を行いやすい構成を目指す
- 今後、機能追加や改善を進めていくためのベースリポジトリ

## 進め方
1. 機能要件を整理する
2. 生成ロジックを実装する
3. テストと改善を繰り返す
4. リリースに向けて整備する

## フロントエンド（Phase 3）

React + TypeScript + Vite / React Router / 通常の CSS を使用します。
共通レイアウト、サンプルデータの Overview、手動投稿作成の Create、投稿管理の Content を実装しています。
Create の下書きは localStorage に保存します。SNS 接続・公開、AI 生成、バックエンド、認証はありません。
ブランド選択は画面間で保持されますが、再読み込み時には TUOUGM に戻ります。

### 開発手順

Node.js 22.12 以上（既存環境の Node.js 24 に対応）が必要です。

```sh
npm install
npm run dev
```

表示先は Vite が出力する URL（通常 `http://localhost:5173`）です。

```sh
npm run typecheck
npm run build
npm run preview
```

依存関係の取得には `registry.npmjs.org` への通信許可が必要です。
ブラウザ履歴 API による画面遷移を使用するため、将来静的ホスティングする場合は
アプリのパスを `index.html` に戻す設定が必要です。Vercel 用には `vercel.json` に
SPA のリライトを定義しています（`/create` の直接アクセス・再読み込みに対応）。

### 構成

- `src/brands/`: ブランド設定と共通 Context
- `src/components/`: 共通レイアウト・ナビゲーション
- `src/data/`: ブランド別 Overview サンプルデータと日時整形
- `src/pages/`: Overview、Create、Content、未実装画面の案内
- `src/posts/`: 下書きの型・検証、保存リポジトリ、ブランド別の編集状態
- `src/styles/`: デザイントークンとレスポンシブ CSS

### 手動確認

1. Overview の「サンプルデータ」表示、4枚のサマリー、投稿予定、履歴を確認。
2. ブランドを TUOUGM → RE:NA → TUOUGM と切り替え、数値・タイトル・履歴・色を確認。
3. Create・Content の相互移動とブランド保持、Calendar・Settings の準備中表示を確認。
4. 375px・320px・768px・1440px 幅で横スクロールがないことを確認。
5. スマートフォンのメニューを開き、Tab 移動・Escape・閉じるボタンを確認。
6. キーボードでブランド選択、全リンク、本文スキップ、戻る・進むを確認。


### Create の使い方と保存仕様

1. 投稿先 SNS（Instagram / Threads / Facebook / X）を選択し、投稿テーマを入力します。
2. 「投稿文を手動で作成」でエディタへ移動し、各 SNS のタブで本文を編集します。補足指示は任意です。
3. 「下書き保存」で、このブラウザに保存します。テーマのみ必須です。SNS未選択・本文が空でも保存できます。
4. 「保存済み」と保存日時を確認します。編集後は「未保存の変更あり」と表示されます。

- `/create` は新規投稿、`/create?draft=<postId>` は既存編集です。初回保存は新規登録し、保存成功後は同じ投稿の編集URLに置き換えてCreateに留まります。
- `/content` でブランド別の複数下書きを更新順に管理します。SNSフィルターは選択中媒体を対象とし、1投稿を1件として表示します。削除は「その他」から確認後に実行します。
- データには投稿 ID、ブランド ID、`draft` ステータス、作成・更新日時（ISO 8601）、revision、テーマ、補足指示、選択 SNS、各 SNS の独立した本文を保持します。
- 保存キーは `sns-generator:drafts:v2:<brandId>`、形式は `{ version: 2, brandId, posts, legacySource }` です。保存処理は `DraftRepository` に分離し、list/get/create/update/deleteを提供します。
- v2がない場合のみv1を検証・移行します。旧ID・本文・日時を保持し、保存後に読み戻して確認します。v1は削除せず、v2に移行元の文字列を記録します。削除後も空のv2を保持し、旧投稿を再移行しません。
- v2破損・未知形式・別ブランド混入・v1の移行後変更は安全なエラーとして停止します。元データを自動初期化・無条件マージしません。旧版のタブは閉じて利用してください。
- SNS の選択を外しても本文は保持します。再選択すれば編集を再開できます。
- 未保存の編集はブランド切り替え・アプリ内の画面移動でもメモリに保持します。再読み込みやタブを閉じる前には保存してください（未保存時はブラウザ標準の離脱確認を要求します）。
- ブランド選択自体は再読み込みで TUOUGM に戻ります。RE:NA の保存済み下書きはブランドを選び直すと復元します。
- 保存失敗時は成功表示にせず、入力を保持して再試行できます。読み込み失敗・形式不正・別ブランドのデータ検出時は編集と保存を停止し、既存データの上書きを防ぎます。
- 保存は同じブラウザ・同じオリジン限定です。Preview URL が変わると別の保存領域になります。端末間同期・ブラウザデータ削除後の復旧はありません。
- revision不一致や更新対象の削除を検出すると上書きを止めます。入力を控えたうえで、確認操作後に保存データを再読み込みできます。Web Locksは使用せず、localStorageでの完全な同時更新防止は保証しません。
- 未保存編集はブランドID＋投稿IDで保持します。新規の作業を再開するか、確認後に破棄して新規作成できます。削除成功時のみ該当投稿の編集キャッシュを破棄します。
- AI ボタンは「未実装」と表示し無効化しています。本文は自動生成しません。プレビューはテキスト表示の参考で、実際の表示や投稿可否を保証しません。
- Overview の件数・履歴は引き続き固定サンプルで、Create の保存結果とは連動しません。

### 保存処理・ブラウザ検証

Python の Playwright と Chromium がある環境で、以下を別ターミナルから実行します。アプリの依存パッケージの追加はありません。

```sh
npm run build
npm run preview -- --port 4173
python3 tests/create_browser.py
python3 tests/content_browser.py
```

`BASE_URL`、`CHROMIUM_PATH` で接続先・ブラウザを変更できます。`SCREENSHOT_DIR` 指定時は画面キャプチャを保存します。
テストは専用ブラウザコンテキストで動作し、実ユーザーの保存データは使用しません。
検証対象：320 / 375 / 768 / 1024 / 1440px、両ブランド、SNS 別編集、保存・再読み込み、ID/日時、
ブランド分離、未保存の画面移動、未入力・空白、容量不足・保存拒否、JSON/スキーマ不正、読み込み拒否と再試行。

承認済み Create カンプの `blob:` URL はクラウド環境から参照できないため、現時点のレイアウトは
既存トークンと指定の左右2カラム構成を基準にしています。カンプ画像との照合は未実施です。


Node.js 24で保存リポジトリのテストを直接実行できます（追加依存なし）。

```sh
node tests/draftRepository.test.mjs
```

不正・別ブランド・削除済み投稿URL、投稿間の未保存編集、各画面幅での横スクロール防止。
